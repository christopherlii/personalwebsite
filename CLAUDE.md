# CLAUDE.md

## Project Overview

Personal website for Christopher Li (www.christopherli.dev). A static site with no framework — just HTML, CSS, and vanilla JS. Hosted on GitHub Pages.

## Architecture

- **Single-page app** using hash-based routing (`#thoughts`, `#favorites`, `#stats`, etc.) handled in `static/markdown-renderer.js`
- **`index.html`** — the single HTML entry point with all views defined inline (home, writing, article, reading, favorites, stats)
- **`static/markdown-renderer.js`** — the `Site` class: routing, markdown rendering (via vendored `marked`), the banner, data loading
- **`styles/main.css`** — the whole stylesheet. (`filters.css` and `archives.css` are left over and not linked from `index.html`.)
- **One shared banner** sits above every view: a sticky photo header holding the breadcrumb and social links, with `--banner-top` (68px) of air above it. The image and everything painted into it live in `.banner-frame`, which is what clips; `.banner` itself is `overflow: visible` so the chrome can leave the box. It opens to `--banner-height` and shrinks with the scroll down to `--banner-bar` — height tracks how far you have read, not which page you are on. Info is the exception: it collapses the image away entirely (height 0). On phones the banner is not sticky — it scrolls away natively. The image is decided by the view alone — nothing hover- or click-driven swaps it. Home shows the photograph (`hero/rock.jpg`); every other view without a cover of its own shows `hero/rock-drawn-hero.jpg` — the painting baked as the photo's aligned twin (`.context/bake_hero_card.py`), revealed through a torn-edged window (`.cropped`) below the chrome; leaving home, one window crops in while the photo dissolves into the painting inside it, and the figure keeps his exact screen position. Articles show their own `cover` in the same card frame; leaving one for the writing list cross-fades the cover back into the painting — the same dissolve that brought it in, in reverse. Only home is full-bleed with white chrome on the photograph. See `setupBanner()`, `drawnPhoto()`, and the `.banner` rules in `main.css`.
- **Lifted chrome** (`.banner.lifted`, `chromeIsLifted()`): on favs and info the name and icons leave the bar entirely rather than sitting on an image — the name rises into the band above the hero (`--chrome-rise` sets how tightly it hugs it, independent of `--banner-top`), and on favs the icons step into the gutter and stack down the hero's right edge. Favs earns this because it deals a different set of photographs every time and no fixed treatment keeps white type legible over all of them; info has no image at all (`.banner.bare` also keeps the icons a row and drops the panel shadow). Under 760px the gutter runs out and the column folds back into a row beside the name. Lifted views are `ink` — dark type on the page — so `setBannerMode()` tracks two independent boundaries: whether the *image* travels (full-bleed vs card) and whether the *text* restyles (photo vs page).

## Content

Writing uses the source selected by `writing-source.json`. The legacy `/posts` setting reads Markdown from the private `christopherlii/site-content` checkout at `content/`. The configured HTTPS `/public/posts` source reads only explicitly published database snapshots. Private entries and later draft saves are never returned publicly. The original four posts have been imported with their publication statuses preserved.

`site-content` continues to supply reading/favorites data and existing media. It is gitignored here and mirrors the site's paths. Clone with `git clone git@github.com:christopherlii/site-content.git content`. Existing Markdown remains a migration/backup source after cutover; manage new writing in the journal. Paths below are relative to `content/`.

- **`posts/`** — blog posts as `.md` files with YAML front matter (`title`, `date`, `tags`, `description`, optional `cover` + `coverPosition`). Index: `posts/index.json` — an array of metadata objects (file, title, date, description, cover, word count) generated by `build.py`, so lists render without fetching post bodies; bodies load on demand. `cover` is the image shown in the banner card at the top of the article; `coverPosition` is a CSS `background-position` for its crop. Posts without a `cover` fall back to the home photo. `description` is kept for metadata/RSS but is not rendered — the article header is title + date + reading time.
- **`reading/index.json`** — reading list entries
- **`solaces/index.json`** — the favs page: categories of `items`, each with a single `previewImage` or a `photos` array (site-absolute paths; drop files under `static/images/favs/<category>/`). The favs hero is a 3x2 tile grid: a category button deals only that category's photos (random six when the pool is bigger), "randomize" deals from every pool, and a category with no photos renders its button disabled until some exist. Pressing the favs crumb while already on favs is a reshuffle, not an arrival — it deals over the tiles that are up rather than clearing the grid and baring the hero beneath. Arriving at favs never swaps the banner image — the previous hero stays beneath while the hand deals over it (over bare page on a cold load); leaving for home, the tiles assemble into the home photo slice by slice

## Build

- **`build.py`** — reads the configured published database export for the legacy RSS feed. `--site DIR` assembles tracked site files with content media/reading/favorites, excluding old Markdown/index files, backend code, and unpublished draft images (unless published content references them). A failed database export fails the build. The `/posts` setting retains the old Markdown build flow for migration only.
- **`.github/workflows/deploy.yml`** — deploys to GitHub Pages: checks out `site-content` (via the `CONTENT_DEPLOY_KEY` secret, a read-only deploy key), runs `build.py --site _site`, publishes it. Runs on push to main and daily at 09:17 UTC, changed or not, so the public run list never reveals when content was published — media updates go live at the next daily run. Journal publish/update/unpublish takes effect directly through the public API. Avoid manual `workflow_dispatch` runs for content; they stand out.
- **`server.py`** — local dev server on port 8001 with markdown content-type support; falls back to `content/` for paths missing at the root. Run with `python3 server.py`.
- `marked` is vendored at `static/vendor/marked.min.js` (no CDN); the site loads assets locally; writing is fetched anonymously from the configured Cloudflare Worker.

## Private journal

`private-journal/` is a separate Cloudflare Worker with D1 storage and owner-only
password login. See its README for local setup, verification, and deployment.
Its entire directory is excluded from the GitHub Pages build. Journal entries
and drafts belong only in the private database, never in this repo or the
public-content assembly. The journal also stores editable public drafts and
explicit published snapshots. Owner exports include private writing and all
publication state; anonymous endpoints serialize only published snapshots.

## Adding a New Post

Create an entry, open its public draft, and explicitly
publish to the site. Later edits stay private until published again. Unpublish
removes the active public snapshot. The public website reads the database
directly, retaining its current article URLs. The daily build updates the legacy
RSS file and copies media/favorites, but no longer copies Markdown bodies or
the old writing index into the public artifact.

For migration or an explicitly configured legacy `/posts` source only:

1. Create `content/posts/your-post-slug.md` with front matter (add `published: false` to keep it a draft):
   ```
   ---
   title: "Post Title"
   date: "YYYY-MM-DD"
   tags: ["tag1", "tag2"]
   description: "Short description"
   cover: "/static/images/blogs/your-post-slug/cover.jpg"
   coverPosition: "center 70%"
   ---
   ```
2. Run `python3 build.py` to regenerate `index.json` and `feed.xml` for local preview
3. Commit and push in `content/`; it goes live at the next daily deploy (09:17 UTC)

## Style Notes

- Fonts: Fraunces (headings) and Instrument Sans (body), self-hosted as variable woff2 subsets in `static/fonts/` (declared in `main.css`, two latin regulars preloaded from `index.html`)
- Type scale: 30px Fraunces page titles, 20px h2, 17px h3, 14px body copy, 13px meta, 14px captions in `--fg-muted`
- Column is 640px wide (`--col`) with 24px gutters; figures use an 8px radius
- Home uses `/static/images/hero/rock.jpg` as its banner photo; articles use their own `cover`
- The site uses a warm, minimal aesthetic with subtle animations (view fade-in, banner collapse, photo shuffle)
- First-paint choreography is pure CSS: the page settles top to bottom via `.page-entrance` + `entrance-*` utility classes (banner chrome first, then home content), list views cascade rows via `.stagger-children` (50ms per child). Both respect `prefers-reduced-motion`. Fraunces/Instrument Sans have metric-matched local fallbacks (`size-adjust` etc.) so the font swap doesn't reflow
- Lowercase writing style throughout the site content, post prose included: sentence starts and the pronoun "i" are lowercase, proper nouns (Bobst, New York, NYU, LinkedIn) keep their capitals
